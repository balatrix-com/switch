# Billing Switch Console

Responsive Super Admin frontend for the billing switch routing API. This project does not implement login, token verification, application users, wallets, or customer impersonation. Those responsibilities remain in the parent platform.

## Run locally

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

The default API URL is `http://localhost:3100/api/v1`. Change `VITE_API_BASE_URL` in `.env` when the backend uses another host or port.

## Request scope

- Global and carrier APIs are called without a customer header.
- Customer endpoints, numbers, routes, and source identities include `X-Customer-ID`.
- No `Authorization` header is generated by this application.

## Main screens

- Routing dashboard
- Customer list and routing details
- Customer IP gateways, default normalization, outbound routes, DIDs, and DID-level settings
- Ordered normalization profile editor with an input/output preview
- Customer outbound and carrier inbound configuration preview
- Carrier list, default normalization, endpoint/source-IP details, and prefix routes
- Global DID inventory, assignment, and provisioning
- Global IP authentication registry
- Global outbound route registry
- API connection and testing reference

Modules that belong to the wider billing application are shown as explicit integration placeholders until their upstream APIs are available.

## Verification

```powershell
npm run lint
npm run build
```

The backend Swagger UI is available at `http://localhost:3100/api/docs` when the API is running.

Every backend HTTP request is written to the Nest console with its request ID, method, path, status, duration, customer context, and source IP. Request bodies and authorization values are intentionally not logged.
