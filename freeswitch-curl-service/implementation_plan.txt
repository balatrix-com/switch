# Implementation Plan: Individual Number-Level Call Recording Toggle

Enable per-number (DID) call recording control after recording has been enabled at the customer level. When recording is toggled for an individual number or a selected batch of numbers, the system regenerates the FreeSWITCH dialplan XML (adding or omitting the 3 recording actions) and refreshes the live route cache.

## Background & Architecture Context

Currently:
1. Call recording is toggled globally per customer via `CustomerSettings.recordingEnabled`.
2. In [did-xml-generation.service.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/route-xml/did-xml-generation.service.ts#L186), DID XML generation only inspects the customer default (`recordingEnabled: defaults?.recordingEnabled ?? false`), applying recording to all numbers if the customer has recording enabled.
3. [route-xml-builder.service.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/route-xml/route-xml-builder.service.ts#L79-L88) emits the 3 FreeSWITCH recording actions when `plan.recordingEnabled` is `true`:
   ```xml
   <action application="set" data="RECORD_STEREO=true"/>
   <action application="set" data="recording_follow_transfer=true"/>
   <action application="set" data="execute_on_answer=record_session /var/lib/freeswitch/recordings/{customerId}/${uuid}.mp3"/>
   ```
4. FreeSWITCH reads the generated XML via `freeswitch-curl-service` (`route_server.py`), which caches routes in memory and exposes `/admin/cache/flush`.

---

## User Review Required

> [!IMPORTANT]
> **Recording Hierarchy & Default Behavior**:
> - **Customer Level Must Be Enabled**: If customer-level recording (`customerSettings.recordingEnabled`) is `false`, recording is disabled for all numbers regardless of number-level settings.
> - **Default When Customer Recording Is Enabled**:
>   - Option A (Default ON / Opt-Out): When customer recording is ON, all numbers record by default (`recordingEnabled: true`), but the customer can toggle specific numbers OFF.
>   - Option B (Default OFF / Opt-In): When customer recording is ON, no numbers record until explicitly toggled ON.
>   
>   *Recommendation*: Implement **Option A** (`recordingEnabled ?? true` when customer recording is active), so existing behavior is preserved until a customer specifically turns off a number or sets a batch.


### 2. Backend API & DTOs

#### [MODIFY] [update-number-settings.dto.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/customer-numbers/dto/update-number-settings.dto.ts)
- Add validation decorator:
  ```typescript
  @IsOptional() @IsBoolean() recordingEnabled?: boolean | null;
  ```

#### [MODIFY] [did-xml-generation.service.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/route-xml/did-xml-generation.service.ts)
- In `generate()`, compute effective recording status:
  ```typescript
  const customerRecordingEnabled = defaults?.recordingEnabled ?? false;
  const numberRecordingOverride = settings?.recordingEnabled;
  const recordingEnabled = customerRecordingEnabled && (numberRecordingOverride ?? true);
  ```
- Pass `recordingEnabled` into the resolved call plan.

#### [MODIFY] [routing.service.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/routing/routing.service.ts)
- In `resolveInbound()`, apply the same number-level override resolution:
  ```typescript
  recordingEnabled: (defaults?.recordingEnabled ?? false) && (numberSettings?.recordingEnabled ?? true),
  ```

> [!NOTE]
> [customer-numbers.service.ts](file:///d:/bala_billing/b-switch/billing-switch/backend/src/customer-numbers/customer-numbers.service.ts) already automatically calls `didXml.generate()` (for single edits) and `didXml.generateBulk()` (for bulk edits), which updates `route_xml` and sends a cache flush request to `freeswitch-curl-service`. No extra cache flush plumbing is needed.
