# Bulk Edit Customer DIDs with Scenario B (Database-Only XML Storage)

This plan implements a **Bulk Edit** capability for assigned Customer DIDs in `billing-switch`, while switching the XML materialization strategy for bulk operations to **Scenario B (Database-Only)**. Under Scenario B, generated FreeSWITCH dialplan XML is stored directly in PostgreSQL (`route_xml.xml_content`), completely bypassing disk writes (`fs.writeFile`), removing any obsolete disk files, and relying on `route_server.py`'s automatic in-memory caching (`ROUTE_CACHE`) and single-token cache flush.

## User Review Required

> [!IMPORTANT]
> **Storage Strategy in Scenario B**:
> When numbers are bulk updated, their `route_xml.fileName` in PostgreSQL will be set to `NULL` and the raw dialplan XML will be stored in `route_xml.xmlContent`. Any older `.xml` file on disk for that DID will be cleanly removed to avoid stale disk reads. When FreeSWITCH receives a call, `route_server.py` will read the XML from the database on the first call, cache it in Python RAM (`ROUTE_CACHE`), and serve all subsequent calls directly from memory without touching the disk or re-querying the database.

> [!TIP]
> **Single Flush Optimization**:
> During bulk edits of 200 numbers, `XmlCurlCacheService.flush()` will be triggered **once** at the end of the batch operation instead of 200 times. This eliminates HTTP round-trip overhead and avoids locking the cache during execution.

## Open Questions

> [!NOTE]
> **Field Overwrite Behavior in Bulk Edit Form**:
> When a user selects 200 numbers and edits them in the bulk drawer, should fields left empty in the form **keep their existing individual values** (e.g. keep each number's existing failover number if the bulk failover input is left blank) or should only actively checked / specified fields be updated?
>
> *Proposed default*: We will treat unspecified/empty fields as "Keep Existing" so that users can bulk change only the Primary Endpoint or Egress Profile without accidentally wiping custom Caller IDs or Forward Numbers.

### Backend: Route XML & DID Generation Layer

#### [MODIFY] [route-xml.service.ts](file:///d:/bala_billing/billing-switch/backend/src/route-xml/route-xml.service.ts)
- Add optional configuration parameter to `materializeDid`:
  ```typescript
  materializeDid(
    customerId: string,
    customerNumberId: string,
    matchNumber: string,
    xmlContent: string,
    options?: { dbOnly?: boolean; skipFlush?: boolean }
  )
  ```
- When `options?.dbOnly` is `true`:
  - Skip `mkdir` and `writeFile` to disk.
  - If `existing?.fileName` exists, delete the old file from disk using `removeFileAndMaybeFlush(existing.fileName, false)`.
  - Upsert `routeXml` record with `fileName: null`, `xmlContent`, and `configHash`.
  - If `options?.skipFlush` is not set, flush the cache; if `true`, skip flush (to allow bulk caller to flush once at the end).

#### [MODIFY] [did-xml-generation.service.ts](file:///d:/bala_billing/billing-switch/backend/src/route-xml/did-xml-generation.service.ts)
- Update `generate` to accept `options?: { dbOnly?: boolean; skipFlush?: boolean }` and forward it to `this.xmlStorage.materializeDid`.
- Add a helper `generateBulk(customerId: string, customerNumberIds: string[], options?: { dbOnly?: boolean })` that generates plans for each number, materializes them with `dbOnly: true, skipFlush: true`, and executes a single cache flush at the end.

### Backend: Customer Numbers Controller & Service

#### [NEW] [bulk-update-number-settings.dto.ts](file:///d:/bala_billing/billing-switch/backend/src/customer-numbers/dto/bulk-update-number-settings.dto.ts)

  ```typescript
  export class BulkUpdateNumberSettingsDto {
    @IsArray()

    customerNumberIds: string[];

    @ValidateNested()
    @Type(() => UpdateNumberSettingsDto)
    settings: UpdateNumberSettingsDto;

    @IsOptional()
    @IsBoolean()
    dbOnly?: boolean;
  }
  ```

#### [MODIFY] [customer-numbers.controller.ts](file:///d:/bala_billing/billing-switch/backend/src/customer-numbers/customer-numbers.controller.ts)
- Add route `@Patch('bulk-settings')` (placed above `@Patch(':id/settings')` to avoid router param collision).
- Expose `bulkUpdateSettings(@CustomerId() customerId: string, @Body() dto: BulkUpdateNumberSettingsDto)`.

#### [MODIFY] [customer-numbers.service.ts](file:///d:/bala_billing/billing-switch/backend/src/customer-numbers/customer-numbers.service.ts)
- Implement `bulkUpdateSettings(customerId: string, dto: BulkUpdateNumberSettingsDto)`:
  - Validate customer ownership of all `dto.customerNumberIds`.
  - Validate destination targets (endpoint IDs, target SIP user, carrier endpoint) once against the customer.
  - Apply the requested settings to `numberSettings` for all target numbers in a batch / transaction.
  - Generate XML for each number with `dbOnly: true, skipFlush: true`.
  - Trigger `this.xmlCurlCache.flush()` once at the completion of the bulk update.
  - Return `{ updated: number, failed: Array<{ id: string; error: string }> }`.
